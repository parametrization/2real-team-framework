## Per-artifact notes

- **`ontology_gen` (crown jewel).** Self-contained Python package, stdlib-only, no network/DB/LLM.
  `model.py` fixes the public `code-graph.json` contract (nodes `{id,kind,path,line,lang}`, edges
  `{src,dst,type}`) with frozen enums and a total-order sort+dedup so output is byte-deterministic and
  git-diffs are record-granular. `generate.py` discovers via `git ls-files` (respects .gitignore) with an
  `os.walk` fallback, dispatches per-language, and degrades a single unparseable file to a bare node instead
  of aborting. `assemble.py` does conservative cross-file edge resolution (emit only unambiguous targets).
  `llms.py` renders a token-economical, per-file-section-loadable digest (~24k vs graphify's ~630k — the
  eval-winning property). `merge_driver.py` is a git union merge-driver that makes parallel regenerations
  conflict-free. The only project coupling is `aggregate.DEFAULT_REPOS` (hardcoded 8-repo map) — already
  overridable via `--repo NAME=SUBDIR`, so genericisation is deleting the default, not rewriting logic.

- **Two-layer model docs (README, checksums contract).** The C×T2 split — generated structural vs.
  hand-curated semantic, with the tracker/resolver scoped to the semantic overlay only and the structural
  layer always-current-by-regeneration — is the reusable architecture. Genericise by swapping domain
  examples and shipping `checksums.json` as an empty template.

- **Semantic overlay YAML (domain/services/repos).** PROJECT-SPECIFIC *content* on a GENERIC *schema*.
  The schema (contexts→entities→typed fields/fk/enums; services→routes/dispatch-contracts; repos→
  modules/build_commands/structural_ref) is a strong template — ship one trimmed example of each, drop bulk.

- **settings.json hook-wiring.** Exact, reusable pattern (dispatcher fan-out + per-matcher hooks across
  Pre/Post/SessionStart/Stop). Only blocker is hardcoded absolute paths → `${CLAUDE_PROJECT_DIR}`.

- **check-mermaid.py / gen-office.sh.** Both are clean reusable CI/doc-gen utilities; check-mermaid ships
  verbatim, gen-office needs the manifest path + project epoch parametrised.

- **TOOLCHAIN.md.** Stack-opinionated (ruff pins, Python 3.14) but the zsh-safety and structural-tooling
  (ast-grep/yq/sd) guidance is broadly valuable — keep as a starter doc with pins stripped.

## Generic two-layer ontology/memory model (framework overview)

The framework's ontology is two cooperating layers that never contaminate each other. The **structural
layer** is *generated* from source by `ontology_gen`: a zero-dependency, offline, deterministic code-graph
(`code-graph.json`) plus a token-economical, section-loadable digest (`llms.txt`) covering files, symbols,
imports, calls, and inheritance — always-current-by-regeneration, so it is never hand-edited and never
checksum-tracked. The **semantic overlay** is *hand-curated* YAML/markdown (domain entities, service map,
conventions, per-repo internals) capturing meaning a parser cannot infer; it is dirty-tracked via a
`checksums.json` contract (a file is dirty when `last_tracked != last_resolved`) and reconciled by a
resolver skill. Three roles tie them together: a PostToolUse **tracker** hook stamps checksums on every edit
to the overlay (skipping the generated layer), a **resolver** skill reconciles dirty overlay entries, and a
read-only **librarian** skill surfaces both layers for context before code changes. The overlay references
generated nodes by stable id (`structural_ref:` / `[[structural:id]]`) rather than re-describing structure,
and a git union merge-driver keeps parallel regenerations of the graph conflict-free. Net: cheap, automatic,
always-fresh structure underneath; deliberate, human-owned meaning on top — and the code is always the
arbiter of truth when the two disagree.
